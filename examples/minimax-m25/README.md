# Osprey on MiniMax-M2.5

Reproduces **Tables 2 and 3**. The drafter starts from the same pretrained
backbone as Qwen3-8B; the target is a 229B FP8 MoE served at tp=4, ep=4.

Hardware: the paper adapts and serves on 4×B200 (192 GB), and **adaptation
needs that much memory**. On H100 80 GB the run dies at the first step with
`CUDA out of memory. Tried to allocate 12.21 GiB` — the target holds ~62 GB per
GPU and the trainer materializes float32 logits for the whole per-replica batch;
this is the same on 4 or 8 GPUs and at tp=8. Evaluation of the released drafter
fits on 4×H100. On Hopper pass `SGLANG_ATTN_BACKEND=fa3`; the default
`flashinfer` is for Blackwell.

Run everything from the repository root after
[Installation](../../README.md#installation), with `OSPREY_OUTPUT` set.

## Training

### Data

Download the released split (70,897 coding conversations, 512 held out) and the
backbone:

```bash
hf download BobbieBieee/Osprey-Speculative-Decoding \
  --include "data/code_*_minimax_m25_4096.jsonl" "pretrained/qwen3-4b-2layer-fineweb-55k/*" \
  --local-dir osprey
```

Prompts come from the code subset of NVIDIA's Nemotron-Post-Training-Dataset-v2
(CC BY 4.0), with responses regenerated by MiniMax-M2.5. The records keep the
Nemotron layout — `uuid` instead of `id`, extra metadata fields, an empty
`system` turn — and the loader accepts them as-is.

Or regenerate the responses yourself from a prompt-side JSONL:

```bash
INPUT_FILE=code_prompts.jsonl OUTPUT_FILE=code_train_minimax_m25.jsonl \
MODEL=MiniMaxAI/MiniMax-M2.5 TP_SIZE=4 REASONING_PARSER=minimax-append-think \
  bash scripts/osprey/regenerate_data.sh
```

### Convert

```bash
python scripts/osprey/convert_checkpoint.py \
  --architecture qwen3 --target minimax-m25 \
  --source-checkpoint osprey/pretrained/qwen3-4b-2layer-fineweb-55k \
  --output-dir "$OSPREY_OUTPUT/qwen3-2l-init-minimax"
```

The preset sets hidden size 3072, tapped layers 1/30/58 of 62, and the
200,064-token MiniMax vocabulary. The alignment report should read
`direct: 97729, single: 134, averaged: 102191, unmapped: 0` — half the rows map
to an exact token and the rest are averages of sub-token rows, which is why the
embedding stays trainable. On the released backbone this reproduces the paper's
Stage-3 output bit for bit.

### Train

```bash
export OSPREY_DRAFT_INIT="$OSPREY_OUTPUT/qwen3-2l-init-minimax"
export OSPREY_MINIMAX_DATA=$PWD/osprey/data/code_train_70k_minimax_m25_4096.jsonl
bash examples/minimax-m25/train.sh
```

4 GPUs, target tp=4 ep=4 with FP8 KV cache, lr 1e-4, TTT length 5, sequence
length 4096, `minimax-m25` chat template. Each GPU is one draft data-parallel
rank, so an epoch is 17,724 steps; the learning-rate schedule spans 3 epochs and
**training stops at `MAX_NUM_STEPS=35000`**, just under 2 epochs, which is the
paper's run. The checkpoint to evaluate is
`$OSPREY_OUTPUT/minimax-m25/osprey/code/epoch_1_step_35000`. Budget ~36 h on
4×B200.

## Evaluation

Evaluation takes 4 GPUs (the FP8 target at tp=4, ep=4). Two suites: `public`
is HumanEval, MATH-500, LiveCodeBench, MT-Bench and Commonsense-Eval at 64
prompts each; `multilingual` is MGSM (64 prompts) and Global-MMLU with English
or native-language answers (84 per language).

### Data

Commonsense-Eval is the commonsense split released with Qwen3-8B; every other
benchmark downloads itself on first use (`openai/openai_humaneval`,
`HuggingFaceH4/MATH-500`, `livecodebench/code_generation`, the FastChat MT-Bench
questions, `juletxara/mgsm`, `CohereLabs/Global-MMLU`).

```bash
hf download BobbieBieee/Osprey-Speculative-Decoding \
  --include "data/commonsense_eval_512_qwen3_8B_4096.jsonl" --local-dir osprey
export OSPREY_DATA=$PWD/osprey/data
```

### Your own checkpoint

`train.sh` stops at step 35,000; evaluate that directory (any intermediate
`epoch_*_step_*` directory works the same way):

```bash
CKPT="$OSPREY_OUTPUT/minimax-m25/osprey/code/epoch_1_step_35000"
```

### Released checkpoint

```bash
hf download BobbieBieee/Osprey-Speculative-Decoding \
  --include "minimax-m25/osprey/*" --local-dir osprey
CKPT=osprey/minimax-m25/osprey
```

### Run

```bash
bash examples/minimax-m25/eval.sh "$CKPT" public
bash examples/minimax-m25/eval.sh "$CKPT" multilingual
bash examples/minimax-m25/eval.sh "$CKPT"                # both
```

The script launches SGLang itself (an FP8 MoE needs `--ep-size` and
`--disable-custom-all-reduce`, which the benchmark runner does not forward) and
then drives it with `--skip-launch-server`: `(1, 5, 1, 6)`, `max_tokens` 4096,
greedy. Results land in `$OSPREY_OUTPUT/results/<name>-<suite>/` as JSON plus a
flat CSV, where `<name>` is `osprey-code` for the trained checkpoint and `osprey`
for the released one; set `RESULT_NAME` to choose it yourself.

### Result

HumanEval, MATH-500, LiveCodeBench, MT-Bench, Commonsense-Eval;
64 prompts each: aggregate accepted length **3.232** for Osprey against 2.634
for the public EAGLE-3 head (+22.7%), with 17.5% higher throughput.

Multilingual:

| Suite | EAGLE-3 AL / tok/s | **Osprey** AL / tok/s |
| --- | --- | --- |
| MGSM (11 languages, 64 prompts) | 2.275 / 167.3 | **2.557 / 179.7** |
| Global-MMLU (42 languages, 84 each) | 2.633 / 197.5 | **3.259 / 231.0** |
| Global-MMLU, native-language answers | 2.620 / 193.7 | **3.023 / 209.9** |
